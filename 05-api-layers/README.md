# 05. API 계층 — 여덟 가지 방식

## 무엇을 배우는가

01부터 04까지는 **프로토콜**을 다뤘다. 이 폴더는 그 위에 얹히는 **API**를 다룬다.

둘은 맞서는 개념이 아니다.

```
  [ 개발자가 만든 서비스 / 앱 ]
               │
               ▼
┌──────────────────────────────────────────────┐
│  ▶ API (Application Programming Interface)    │ ◀ 개발자가 잡는 "조작 핸들"
└──────────────────────┬───────────────────────┘
                       │ (API 명령이 하부 스택을 깨운다)
                       ▼
┌──────────────────────────────────────────────┐
│  4층. 어플리케이션 계층 (MQTT, HTTP 등)       │ ──┐
├──────────────────────────────────────────────┤   │
│  3층. 전송 계층 (TCP, UDP)                   │   ├─► [ TCP/IP 프로토콜 스택 ]
├──────────────────────────────────────────────┤   │   (데이터를 실제로 나르는 엔진)
│  2층. 인터넷 계층 (IP)                       │   │
├──────────────────────────────────────────────┤   │
│  1층. 네트워크 인터페이스 계층 (Wi-Fi, 이더넷)│ ──┘
└──────────────────────────────────────────────┘
```

스택은 엔진이고 API는 그 엔진에 달아 놓은 조작 핸들이다. 자동차를 몰 때 실린더의 움직임을 몰라도 페달만 밟으면 되는 것과 같다.

다만 **API가 붙는 자리는 하나가 아니다.** 소켓 API는 애플리케이션과 3층 전송 계층 사이에 붙는다. MQTT 라이브러리 API는 4층 위에 얹힌다. REST와 GraphQL은 HTTP 위에 다시 규약을 하나 더 세운 것이다. 그래서 "API는 스택 맨 위"라고 뭉개면 이 차이가 안 보인다. 이 폴더가 그 차이를 코드로 갈라 놓는다.

## 이 폴더의 실습 방법

**같은 일을 여덟 가지 방식으로 구현한다.**

```
get()          최근 센서 값을 읽는다
set(value)     값을 올린다
```

이 둘뿐이다. 자료는 [`common/store.py`](common/store.py)에 한 번만 적어 두고 여덟 폴더가 함께 쓴다. API 방식만 다르고 아래에 놓인 자료는 같아야 견주는 뜻이 있다.

## 여덟 폴더

| 폴더 | 방식 | 아래 계층 | 바깥 패키지 |
|---|---|---|---|
| [`01-socket-api/`](01-socket-api/) | 소켓 API + 내가 만든 규약 | TCP | 없음 |
| [`02-library-api/`](02-library-api/) | 프로토콜 라이브러리 | HTTP | 선택 (`requests`) |
| [`03-rest-api/`](03-rest-api/) | REST | HTTP | 없음 |
| [`04-graphql-api/`](04-graphql-api/) | GraphQL | HTTP | 없음 |
| [`05-grpc-api/`](05-grpc-api/) | gRPC | HTTP/2 + protobuf | **`grpcio` 필요** |
| [`06-websocket-api/`](06-websocket-api/) | WebSocket + JSON-RPC 꼴 | WebSocket | 없음 |
| [`07-webhook/`](07-webhook/) | Webhook (방향이 뒤집힌다) | HTTP | 없음 |
| [`08-sdk-wrapper/`](08-sdk-wrapper/) | SDK | REST 위에 얹는다 | 없음 |

## 한 번에 견주기

```
python3 compare.py
```

서버를 차례로 띄우고 같은 일을 시켜 코드 줄 수, 왕복 시간, 본문 크기를 잰다. 실제로 돌려 나온 값이다.

```
방식                  코드 줄     왕복 ms       본문 바이트
소켓 API               128      0.12            8
REST                 134      0.49           78
SDK                  165      0.45           77
GraphQL              192      1.03           40
gRPC                 154      0.23           34
WebSocket API        272      0.21           97
```

Webhook은 이 표에 없다. '클라이언트가 부른다'는 잣대 자체가 맞지 않기 때문이다. 서버가 클라이언트를 부르므로 왕복 시간을 같은 뜻으로 잴 수 없다.

### 표를 읽을 때 조심할 것

**코드 줄이 적다고 좋은 것이 아니다.** 소켓 API가 가장 짧게 나오지만, 그 짧은 코드가 규약, 오류 표현, 자료 모양, 판본 관리를 모두 떠안고 있다. 남이 내 API를 쓰려면 문서를 읽고 그 규약을 손으로 구현해야 한다. gRPC는 `.proto`와 생성 코드가 줄 수에 빠져 있다.

**왕복 시간은 모두 루프백이다.** 실제 망에서는 순서가 달라질 수 있다. 특히 연결을 매번 새로 맺는 REST와 한 번 맺어 두는 WebSocket·gRPC의 차이가 지연이 큰 망에서 벌어진다.

**본문 바이트는 애플리케이션이 본 크기다.** 선 위의 전체 바이트에는 TCP·IP·이더넷 헤더가 더 붙는다. [06-encapsulation](../06-encapsulation/)이 그것을 센다.

## 계층을 올릴 때 생기는 일

같은 값 하나를 읽는 코드를 계층별로 늘어놓으면 이렇게 된다.

```
소켓        sock.sendall(b"GET\n"); reply = sock.recv(256)
http.client conn.request("GET", path); body = conn.getresponse().read()
requests    body = requests.get(url).content
SDK         reading = client.get()          # Reading 객체가 온다
gRPC        reading = stub.Get(sensor_id)   # 타입까지 .proto가 정한다
```

내려갈수록 코드가 줄고, **내가 모르는 일이 늘어난다.**

| 계층 | 내가 하는 일 | 내가 모르는 일 |
|---|---|---|
| 소켓 | 경계, 오류, 파싱, 규약 전부 | 없다 |
| 라이브러리 | 메서드와 경로를 고른다 | HTTP 문법, 연결 관리 |
| SDK | 함수를 부른다 | 재시도, 대기, 타입 변환, 요청 횟수 |
| gRPC | 함수를 부른다 | 직렬화, HTTP/2 프레이밍, 스트림 관리 |

편해지는 만큼 문제가 났을 때 안이 안 보인다. [`08-sdk-wrapper/demo.py --trace`](08-sdk-wrapper/)가 그 안을 열어 보여 준다.

## 고르는 기준

| 상황 | 쓸 것 |
|---|---|
| 기기가 좁은 망에 있다, 배터리로 돈다 | CoAP, MQTT ([04-application](../04-application/)) |
| 웹 브라우저가 부른다, 캐시가 필요하다 | REST |
| 화면마다 필요한 필드가 다르다 | GraphQL |
| 서비스끼리 부른다, 속도와 타입 안전이 중요하다 | gRPC |
| 값이 자주 바뀌고 바로 알아야 한다 | WebSocket |
| 상대가 내 서버를 부르게 하고 싶다, 평소 연결이 없어야 한다 | Webhook |
| 남에게 내 API를 쓰게 한다 | REST나 gRPC 위에 SDK를 함께 낸다 |
| 규약을 완전히 내 마음대로 정해야 한다 | 소켓 API |

## 메모

[`03-transport-socket`](../03-transport-socket/)에서 만든 코드가 `01-socket-api`의 출발점이다.

API는 프로토콜 스택과 맞서는 개념이 아니다. 스택이라는 엔진에 달아 놓은 조작 핸들이다. 이 폴더에서는 그 핸들을 여덟 번 바꿔 잡아 본다.
