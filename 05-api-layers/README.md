# 05. API 계층 비교

## 목표
같은 기능 하나를 API 계층만 바꿔 가며 구현한다. 계층을 올릴 때 무엇이 편해지고 무엇이 안 보이게 되는지 적는다.

## 만들 것
같은 기능 하나를 세 계층으로 각각 구현한다.

| 계층 | 쓰는 API | 개발자가 직접 다루는 것 |
|---|---|---|
| 저수준 | 소켓 API (`socket`, `send`, `recv`) | 바이트, 연결 상태, 버퍼 |
| 중간 | 프로토콜 라이브러리 (`requests`, `paho-mqtt`) | 메시지, 주제, 헤더 |
| 고수준 | REST 클라이언트, SDK | 객체와 메서드 |

## 확인하는 법
1. 세 구현의 코드 줄 수를 센다.
2. 연결이 끊겼을 때 각 구현이 어떻게 반응하는지 본다. 어느 계층이 재시도를 알아서 해 주는가.
3. 세 구현을 평문(HTTP)으로 맞춘 뒤 캡처해 견준다. 라이브러리가 어떤 헤더를 알아서 덧붙였는지, 전송 계층에서 오가는 모양은 같은지 본다. HTTPS로 붙으면 TLS 레코드만 보여서 견줄 수 없다.

## 메모
`03-transport-socket`에서 만든 코드가 저수준 구현의 출발점이다.

API는 프로토콜 스택과 맞서는 개념이 아니다. 스택이라는 엔진에 달아 놓은 조작 핸들이다. 이 폴더에서는 그 핸들을 바꿔 잡아 본다.
