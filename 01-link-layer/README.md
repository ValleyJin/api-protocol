# 01. 네트워크 인터페이스 계층 (1층)

## 무엇을 배우는가

이 계층은 **같은 선에 붙어 있는 기기끼리** 데이터를 주고받는 일을 맡는다. 범위가 딱 거기까지다. 옆 건물로 보내는 일은 2층이 하고, 이 계층은 "지금 내가 꽂힌 이 랜 안에서 저 기기에게" 프레임 하나를 건네는 데까지만 책임진다.

그래서 여기서 쓰는 주소가 IP 주소가 아니라 MAC 주소다. MAC 주소는 랜카드에 박혀 나오는 6바이트 값이고, 앞 3바이트는 만든 회사를 가리킨다. IP 주소처럼 지역별로 나뉘어 있지 않아서 라우팅에 쓸 수 없다. 전 세계 MAC 주소 표를 만들 수 없기 때문이다.

이더넷 프레임은 14바이트 헤더로 시작한다.

```
┌──────────────┬──────────────┬───────────┬─────────────────┐
│ 목적지 MAC   │ 출발지 MAC   │ 이더타입  │  그 위 계층     │
│   6바이트    │   6바이트    │  2바이트  │  46~1500바이트  │
└──────────────┴──────────────┴───────────┴─────────────────┘
```

마지막 2바이트인 **이더타입**을 눈여겨본다. 이 값이 "내가 실어 나르는 것이 무엇인지"를 알려 준다. 0x0800이면 IPv4, 0x0806이면 ARP, 0x86DD면 IPv6다. 받는 쪽은 이 값을 보고 다음에 누구에게 넘길지 정한다. 계층은 이렇게 위아래로 이어진다. 2층의 프로토콜 필드, 3층의 포트 번호가 모두 같은 구실을 한다.

### ARP — 주소 두 개를 잇는 다리

여기서 문제가 하나 생긴다. 보내려는 상대의 IP 주소는 아는데 MAC 주소를 모른다. 프레임을 만들려면 MAC 주소가 있어야 한다. 이 간극을 메우는 것이 ARP다.

ARP는 같은 랜 전체에 대고 "192.168.0.1 쓰는 분, MAC 주소가 뭡니까"라고 외친다. 목적지 MAC을 전부 `ff`로 채운 브로드캐스트 프레임으로 보낸다. 그 기기가 "나요, 내 MAC은 이겁니다"라고 답하면 그 값을 캐시에 넣어 두고 쓴다.

ARP는 IP 주소를 다루지만 인터넷 계층 프로토콜이 아니다. IP 헤더 안에 들어가지 않고 이더넷 헤더 바로 뒤에 붙는다(이더타입 0x0806). 라우터를 넘어가지도 않는다. 그래서 이 계층에 속한다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `list_interfaces.py` | 인터페이스와 MAC 주소, IPv4 주소를 뽑는다 |
| `parse_ethernet.py` | 캡처에서 이더넷 헤더를 바이트 단위로 갈라 읽는다 |
| `parse_arp.py` | ARP 요청과 응답을 짝지어 읽는다 |
| `send_arp_request.py` | ARP 요청 프레임 42바이트를 직접 만들어 내보낸다 (리눅스) |
| `capture.sh` | `tcpdump`를 감싼 캡처 도우미 |

## 실습

### 1. 내 기기의 1층을 들여다본다

```
python3 list_interfaces.py
```

MAC 주소가 `-`로 나오는 인터페이스가 있다. 루프백(`lo0`, `lo`)이 대표적이고, 터널 인터페이스(`utun0`, `gif0`)도 마찬가지다. 자기 자신에게 보내는 통로라 랜카드가 없고, 그래서 이더넷 헤더도 없다. 이 사실이 06 폴더에서 오버헤드를 셀 때 다시 나온다.

### 2. 프레임을 잡아 헤더를 뜯어본다

```
./capture.sh en0 "" 20
python3 parse_ethernet.py samples/en0-all.pcap
```

인터페이스 이름은 1번에서 본 것 가운데 IP 주소가 붙어 있는 것을 고른다. 출력에서 목적지 MAC, 출발지 MAC, 이더타입이 각각 몇 번째 바이트인지 눈으로 맞춰 본다.

### 3. ARP가 오가는 것을 잡는다

캐시가 살아 있으면 ARP 요청이 나가지 않는다. 먼저 비운다.

```
mkdir -p samples
sudo arp -d -a                      # macOS
sudo ip neigh flush all             # 리눅스

sudo tcpdump -i en0 -w samples/arp.pcap arp &
ping -c 1 192.168.0.1               # 공유기 주소로 바꾼다
sleep 2 && sudo pkill tcpdump
python3 parse_arp.py samples/arp.pcap
```

요청에서 '찾는 MAC'이 전부 0인 것을 확인한다. 모르니까 비워 두고 묻는 것이고, 응답이 그 자리를 채워 돌아온다.

### 4. 프레임을 직접 만들어 내보낸다 (리눅스)

```
sudo python3 send_arp_request.py eth0 192.168.0.1
```

42바이트를 손으로 조립해 랜카드에 바로 넣는다. 운영체제의 TCP/IP 스택을 거치지 않는다. macOS와 BSD는 `AF_PACKET`이 없어 BPF 장치를 써야 한다. 쓰는 법이 꽤 달라 여기서는 건너뛴다. 코드를 읽어 프레임을 어떻게 조립하는지 확인하고, 내보내는 것은 3번 실습으로 대신한다.

## 직접 확인할 것

- **브로드캐스트를 찾아본다.** 목적지 MAC이 `ff:ff:ff:ff:ff:ff`인 프레임이 주기적으로 지나간다. 누가 왜 보내는지 `parse_ethernet.py`로 출발지를 확인한다.
- **MAC 주소의 둘째 비트를 본다.** 출발지 MAC의 첫 바이트에서 둘째 비트가 서 있으면 소프트웨어가 붙인 주소다. 가상 기기나 프라이버시 기능을 켠 기기에서 나온다.
- **캐시가 있을 때와 없을 때를 견줘 본다.** 캐시를 비우지 않고 같은 기기에 다시 `ping`을 보내면 ARP가 나가지 않는다. 캐시가 얼마나 지나야 사라지는지 `arp -a`로 지켜본다.

## 자주 막히는 곳

| 증상 | 까닭 |
|---|---|
| `tcpdump`가 권한 오류를 낸다 | 캡처에는 관리자 권한이 필요하다. `sudo`를 붙인다 |
| 이더넷 헤더가 없다고 나온다 | 루프백이나 `-i any`를 잡았다. 물리 인터페이스를 고른다 |
| pcapng라 못 읽는다고 한다 | Wireshark 기본 형식이 pcapng다. `tcpdump -w`로 뜨거나 `editcap -F pcap`으로 바꾼다 |
| ARP가 하나도 안 잡힌다 | 캐시가 살아 있다. 위 3번대로 비우고 다시 한다 |
