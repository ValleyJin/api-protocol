# 04. 애플리케이션 계층 (4층)

## 목표
성격이 다른 애플리케이션 프로토콜로 같은 기능을 각각 구현해 본다. 무엇이 다르고 왜 다른지 견준다.

## 하위 폴더
| 폴더 | 프로토콜 | 갈래 |
|---|---|---|
| `http/` | HTTP | 요청-응답 |
| `dns/` | DNS | 요청-응답 (이름 풀이) |
| `websocket/` | WebSocket | 양방향 상시 연결 |
| `mqtt/` | MQTT | 발행-구독 메시징 |
| `coap/` | CoAP | 초경량 IoT |

## 만들 것
각 폴더의 「만들 것」을 마친 뒤, 네 폴더(HTTP, WebSocket, MQTT, CoAP)에서 같은 기능을 한 번 더 구현한다. **센서 값 하나를 올리고, 받는 쪽이 그 값을 읽는다.** 그래야 프로토콜끼리 견줄 수 있다.

DNS는 이 공통 과제에서 뺀다. 이름을 푸는 프로토콜이라 값을 올리는 쪽이 아예 없다. `dns/` 폴더는 이름 풀이만 다룬다.

## 확인하는 법
구현한 뒤 아래를 표로 정리해 견준다.

- 연결을 누가 먼저 여는가
- 메시지 한 건의 실제 바이트 수
- 브로커나 서버가 따로 필요한가
- 값이 바뀌었을 때 받는 쪽이 얼마나 빨리 아는가

## 메모
MQTT는 이 다섯 폴더 가운데 하나다. 비교 대상이지 주인공이 아니다.

라이브러리의 `publish()`나 `get()`이 API이고, 그 아래를 흐르는 규약이 프로토콜이다. 둘을 섞지 않는다.

여기서 만든 구현과 캡처가 `06-encapsulation`의 재료가 된다.
