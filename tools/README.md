## 임포트하는 방법

하위 폴더의 스크립트는 맨 위에 이렇게 적는다.

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1]))
from tools.pcap import PcapFile
```

폴더가 두 단계 아래(`04-application/mqtt` 등)면 `parents[2]`로 적는다.

## pcap 파일 구조

`pcap.py`를 읽기 전에 알아 두면 좋다. 24바이트 전역 헤더가 한 번 나오고, 그 뒤에 [16바이트 패킷 헤더 + 데이터]가 끝까지 되풀이된다.

```
전역 헤더 (24바이트)
┌────────┬─────┬─────┬────────┬────────┬────────┬─────────┐
│ magic  │major│minor│thiszone│ sigfigs│ snaplen│ network │
│  4     │  2  │  2  │   4    │    4   │    4   │    4    │
└────────┴─────┴─────┴────────┴────────┴────────┴─────────┘

패킷 헤더 (16바이트)
┌────────┬─────────┬──────────┬──────────┐
│ ts_sec │ ts_usec │ incl_len │ orig_len │
└────────┴─────────┴──────────┴──────────┘
```

`magic` 값이 바이트 순서를 알려 준다. `network` 필드는 링크 계층 종류(linktype)를 나타낸다. 이 값에 따라 패킷 데이터가 무엇으로 시작하는지 달라진다. 이더넷 헤더일 수도 있고, BSD 루프백의 4바이트 AF 값일 수도 있고, 곧바로 IP 헤더일 수도 있다. `06-encapsulation`에서 오버헤드를 셀 때 이 값이 중요하다.

`incl_len`은 파일에 담긴 길이이고 `orig_len`은 네트워크에 실제로 흐른 원래 길이다. `snaplen`을 짧게 걸고 잡으면 둘이 달라진다.

## pcapng는 못 읽는다

이 리더는 예전 pcap만 읽는다. Wireshark의 기본 저장 형식은 pcapng다.

```
tcpdump -w out.pcap                      # 이렇게 뜨면 pcap이다
editcap -F pcap in.pcapng out.pcap       # 이미 pcapng라면 바꾼다
```

pcapng는 블록 구조라 훨씬 복잡하다. 이 저장소의 목적(헤더를 손으로 뜯어보기)에는 단순한 pcap이 알맞다.


## 바이트 표가 맞는지 확인한다

루트 `readme.md` 의 표는 "실제로 돌려 재어 본 값이다" 라고 적어 두었다. 그 말이 참인지
`check_bytes.py` 가 확인한다. 서버를 띄우고 교재가 적어 둔 클라이언트로 재어 표와 맞댄다.

```
python3 tools/check_bytes.py
```

**기대값을 표에서 읽어 온다.** 스크립트 안에 수치를 적어 두면 표를 고쳤을 때 검사가 옛 값을
지키고, 둘이 갈라진 것을 아무도 모른다. 코드 줄 수를 `05-api-layers/compare.py` 로 맞대는
것과 같은 꼴이다.

**흔들리는 값은 최댓값으로 맞댄다.** 본문 길이는 `ts` 끝자리에 따라 한두 바이트 흔들리고
응답도 함께 흔들린다. 허용 범위로 맞대면 그 범위 안의 틀린 값이 통과한다. 그래서 서버를
다섯 번 새로 띄워 가장 큰 값이 표와 같은지 본다.

gRPC 행은 `grpcio` 가 있어야 잰다. 없으면 **안 봤다고 찍고 통과로 세지 않는다.** 다섯 행
가운데 넷만 보고 "맞다" 고 하면 검사가 있다는 말만 남는다. `grpcio` 를 따로 깐 python 이
있으면 `--grpc-python` 으로 알려 준다.

포트가 겹치면 `--port-base` 로 옮긴다. `--ws-port` 는 네 자리여야 한다. 표의 핸드셰이크
284 는 포트 8081 에서 잰 값이고, 포트 자릿수가 늘면 `Host` 헤더가 길어져 285 가 된다.
