# 06. 인캡슐레이션 추적

## 목표
API 호출 한 번이 각 계층에서 어떤 헤더를 덧입는지 끝까지 따라간다. 앞의 다섯 폴더를 하나로 잇는 마무리 실습이다.

## 만들 것
- 캡처 파일 하나를 읽어 프레임 → IP → TCP → 애플리케이션 순으로 헤더를 벗겨 내는 파서
- 각 계층이 덧붙인 바이트 수를 세어 오버헤드 비율을 내는 스크립트
- 같은 메시지를 HTTP와 MQTT로 보냈을 때의 총 바이트를 견주는 표

## 확인하는 법
1. `04-application`에서 만든 발행 한 건을 캡처한다. MQTT가 대표적인 예다. 브로커는 다른 기기나 VM, 컨테이너에 띄우고 물리 인터페이스에서 잡는다. 같은 기기의 루프백에서 잡으면 이더넷 헤더가 아예 없다.
2. 그 패킷 한 개에서 이더넷 헤더 14바이트, IP 헤더 20바이트(옵션이 없을 때), TCP 헤더 20바이트, MQTT 헤더와 페이로드를 각각 짚는다. TCP 헤더는 옵션이 붙으면 늘어난다. 타임스탬프가 켜져 있으면 대개 32바이트다. 캡처에서 데이터 오프셋 값을 읽어 확인한다.
3. 실제 데이터가 전체 바이트에서 차지하는 비율을 낸다.
4. 같은 데이터를 HTTP로 보내고 같은 계산을 해서 견준다.

## 메모
여기까지 오면 1층부터 API까지 한 줄로 꿰인다. 개발자가 돌린 핸들 하나가 어떤 바이트가 되어 실제로 오가는지 눈으로 확인하는 단계다.
