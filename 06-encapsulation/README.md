# 06. 인캡슐레이션 추적

## 무엇을 배우는가

앞의 다섯 폴더를 하나로 잇는 마무리다. API 호출 한 줄이 네트워크에서 어떤 모습이 되는지 끝까지 따라간다.

계층마다 헤더가 덧붙는 것을 **인캡슐레이션**이라고 한다. 위에서 아래로 내려가며 포장이 한 겹씩 씌워진다.

```
[ 개발자가 부른 API ]          client.get()
         │
         ▼  애플리케이션 계층이 규약대로 적는다
┌────────────────────────────────────────┐
│ HTTP: GET /sensors... 또는 MQTT PUBLISH │   ← 04, 05 폴더
└────────────────────────────────────────┘
         │
         ▼  전송 계층이 포트와 순서 번호를 붙인다
┌──────────┬─────────────────────────────┐
│ TCP 헤더 │      애플리케이션 바이트     │   ← 03 폴더
└──────────┴─────────────────────────────┘
         │
         ▼  인터넷 계층이 주소를 붙인다
┌─────────┬──────────┬────────────────────┐
│ IP 헤더 │ TCP 헤더 │  애플리케이션      │   ← 02 폴더
└─────────┴──────────┴────────────────────┘
         │
         ▼  링크 계층이 MAC 주소를 붙인다
┌──────────┬─────────┬──────────┬─────────┐
│ 이더넷   │ IP      │ TCP      │ 앱      │   ← 01 폴더
└──────────┴─────────┴──────────┴─────────┘
```

받는 쪽은 이 순서를 거꾸로 밟아 한 겹씩 벗긴다. 각 계층 헤더에 "다음은 누구"를 적어 둔 까닭이 여기 있다(이더타입 → 프로토콜 번호 → 포트 번호).

## 파일

| 파일 | 하는 일 |
|---|---|
| `peel.py` | 패킷 한 개를 계층별로 벗겨 낸다 |
| `overhead.py` | 캡처 전체를 훑어 계층별 오버헤드를 세고 프로토콜을 견준다 |
| `samples/sample.pcap` | 실습용 표본(지어낸 캡처다. 아래를 읽는다) |

## 표본 캡처에 관한 경고

`samples/sample.pcap`은 **잡은 캡처가 아니라 지어낸 캡처다.** `../tools/make_sample_pcap.py`가 이더넷, IP, TCP 헤더를 규격대로 조립해 파일로 적은 것이다. 바이트는 진짜와 같은 규격이지만 실제 망에서 오간 것은 아니다.

캡처를 뜨려면 관리자 권한이 필요해서, 권한이 없는 사람도 파서를 돌려 볼 수 있게 만들어 두었다.

**직접 캡처를 뜰 수 있으면 그쪽을 쓴다.** 진짜 캡처에는 재전송, 순서 뒤바뀜, 다양한 TCP 옵션, 다른 흐름의 패킷이 섞여 있다. 여기서 만든 것에는 그런 것이 없어 깨끗하다. 이것으로 파서를 익히고 진짜 캡처로 확인한다.

```
python3 ../tools/make_sample_pcap.py samples/sample.pcap    # 다시 만들 때
```

## 실습

### 1. 한 프레임을 벗겨 본다

```
python3 peel.py samples/sample.pcap
python3 peel.py samples/sample.pcap -n 5 --hex
```

계층마다 헤더가 몇 바이트고, 벗기면 얼마가 남는지 찍는다. 막대그래프로 비율도 보여 준다.

이 출력에서 **TCP 헤더가 20이 아니라 32**로 나온다. 타임스탬프 옵션이 붙어서다. 여기를 눈여겨본다. 요즘 운영체제는 이 옵션을 기본으로 켠다. 20으로 고정해 세면 계산이 어긋난다. 데이터 오프셋 필드를 읽어야 한다.

### 2. 전체를 세고 프로토콜을 견준다

```
python3 overhead.py samples/sample.pcap
```

표본 캡처로 돌리면 이렇게 나온다.

```
프로토콜   프레임    1층   2층 IP  3층 TCP   4층 앱     합계   앱 비율
HTTP          7      98     140      232     325      795    40.9%
MQTT          8     112     160      264     137      673    20.4%
```

**이 표본에서는 프레임마다 66~70바이트가 그냥 붙는다.** 1층 14 + 2층 20 + 3층 32~36이다. TCP 헤더가 20바이트로 끝나는 프레임이 이 표본에는 없다. 타임스탬프 옵션이 모든 프레임에 붙어 32바이트가 되고, SYN에는 MSS까지 붙어 36바이트가 된다. 센서 값 4바이트를 보내려고 그 열 배가 넘는 바이트가 움직인다.

**이 범위를 외우지 않는다.** 표본은 1층이 늘 14, 2층이 늘 20이라 범위가 좁게 나온다. 진짜 캡처는 이보다 넓다. VLAN 태그가 붙으면 1층이 18, 태그가 두 개면 22가 된다. IP 옵션이 붙으면 2층이 60까지 간다. TCP 옵션은 상한이 40이라 3층도 60까지 간다. 실제 루프백 연결은 타임스탬프와 윈도 스케일, SACK 허용을 함께 협상해 SYN 헤더가 40바이트가 되는 일이 흔하다. 세 층이 겹치면 머리글만 140을 넘는다. `overhead.py`는 이 숫자를 박아 두지 않고 넘겨받은 캡처에서 세어 찍는다. 캡처를 바꿔 가며 그 줄이 어떻게 달라지는지 보는 것이 범위를 외우는 것보다 낫다. 층마다 길이 필드를 먼저 읽어야 하는 까닭이 바로 이것이다.

### 3. 진짜 캡처를 떠서 다시 센다

```
sudo tcpdump -i en0 -w my.pcap port 8080 or port 1883
# 다른 창에서 04-application의 실습을 돌린다
python3 overhead.py my.pcap
```

**브로커나 서버를 다른 기기나 VM에 띄우고 물리 인터페이스에서 잡는다.** 같은 기기의 루프백에서 잡으면 1층이 어긋난다.

- macOS `lo0`은 DLT_NULL이라 이더넷 헤더가 아예 없다(4바이트 AF 값이 대신 붙는다)
- 리눅스 `lo`는 MAC이 전부 0인 가짜 이더넷 헤더가 붙는다

어느 쪽도 실제 링크에서 오가는 프레임이 아니다. `overhead.py`가 이더넷이 아닌 캡처를 만나면 경고를 찍는다.

컨테이너를 쓸 때도 조심한다. `-p 1883:1883`으로 공개한 포트에 `localhost`로 붙으면 트래픽이 루프백으로 흐른다. 컨테이너 IP로 직접 붙어 `docker0` 같은 브리지에서 잡아야 한다. macOS Docker Desktop은 이 길이 없으니 VM이나 다른 기기를 쓴다.

## 숫자를 읽을 때 조심할 것

`overhead.py`는 앞의 표와 함께 "값 1바이트를 나르는 데 몇 바이트를 썼나"도 찍는다. 이 숫자를 곧이곧대로 읽으면 안 된다.

**첫째, HTTP와 MQTT는 실은 서로 다른 것을 나른다.** 표본에서 HTTP는 센서 이름과 단위까지 담은 JSON 72바이트를 보냈고, MQTT는 숫자만 12바이트 보냈다. 값 1바이트당 비용은 많이 담을수록 낮아지니, **말이 많은 쪽이 오히려 좋아 보인다.** 이 잣대 하나로 우열을 가릴 수 없다.

**둘째, 건수가 적어 연결 비용이 통째로 섞여 든다.** HTTP는 연결을 맺고 끊는 데 다섯 프레임을 쓰고 값을 한 번 날랐다. MQTT는 연결 하나로 세 번 날랐다. 건수를 늘리면 MQTT는 PUBLISH 프레임만 늘고 HTTP는 핸드셰이크까지 되풀이한다.

제대로 견주려면 **같은 것을 같은 횟수만큼** 날라야 한다. `04-application/common/sensor.py`가 그래서 있다. 캡처를 직접 떠서 건수를 바꿔 가며 다시 세어 보면 어디서 우열이 뒤집히는지 보인다. 그 지점을 찾는 것이 이 폴더의 진짜 실습이다.

## 직접 확인할 것

- **MTU를 넘겨 본다.** `04-application/http/minimal_server.py`가 2000바이트짜리 본문을 돌려주게 고친다. 물리 인터페이스로 주고받아야 이더넷 MTU 1500을 넘어 TCP가 세그먼트를 나눈다. 루프백은 MTU가 훨씬 커서 안 나뉜다. 오버헤드 비율이 어떻게 달라지는지 센다.
- **QoS를 올려 본다.** MQTT를 QoS 1로 발행하면 PUBACK 프레임이 하나 더 붙는다. 4바이트 값을 보내려고 프레임 하나(54바이트 이상)를 더 쓰는 셈이다. 그 대가를 치를 만큼 안전해지는가.
- **TLS를 얹어 본다.** 이 저장소에는 HTTPS 서버가 없다. `minimal_server.py`의 소켓을 `ssl`로 감싸고 자체 서명 인증서를 만든 다음, 같은 요청을 보내고 캡처를 뜬다. 핸드셰이크 왕복과 레코드 헤더가 더 붙는다. `05-api-layers/08-sdk-wrapper`에서처럼 SDK가 그것을 감춰 줄 때 실제 비용이 얼마인지 여기서 센다.

## 여기까지 오면

계층 이름을 외우는 대신 캡처에서 바이트를 직접 세어 확인할 수 있다. 개발자가 돌린 핸들 하나가 어떤 바이트가 되어 실제로 오갔는지 눈으로 본 셈이다.

여기서 벗겨 낸 바이트는 `04-application`에서 직접 만든 구현이 내보낸 것이다.
