# 🌐 통신 프로토콜 실습

통신 프로토콜을 계층별로 훑고 직접 돌려 보는 실습 모음이다. 특정 프로토콜 하나를 깊게 파는 것이 아니라, 하드웨어에서 애플리케이션까지 스택 전체를 순서대로 밟아 본다. 그리고 스택의 맨 위에 얹혀 사람이 만든 소프트웨어와 스택을 이어 주는 **API**까지 함께 다룬다.

---

## 1. 이론(OSI 7계층)과 실제(TCP/IP 4계층)

OSI 7계층은 교과서의 모형이다. 실제 인터넷은 이를 네 층으로 합친 **TCP/IP 모델**로 돌아간다. 실습도 TCP/IP 4계층을 기준으로 삼는다.

```text
[ 이론: OSI 7계층 ]                 [ 실제: TCP/IP 4계층 ]             [ 역할과 대표 프로토콜 ]
7. 어플리케이션 (Application) ──┐
6. 프레젠테이션 (Presentation) ──┼─►  4층. 어플리케이션 계층  ───────► 소프트웨어 영역 (HTTP, MQTT)
5. 세션 (Session)             ──┘
─────────────────────────────────────────────────────────────────────────────────────────
4. 전송 (Transport)           ───►  3층. 전송 계층 (Transport) ──────► OS 엔진 영역 (TCP, UDP)
─────────────────────────────────────────────────────────────────────────────────────────
3. 네트워크 (Network)         ───►  2층. 인터넷 계층 (Internet) ─────► 주소·경로 영역 (IP)
─────────────────────────────────────────────────────────────────────────────────────────
2. 데이터 링크 (Data Link)    ──┐
1. 물리 (Physical)            ──┴─►  1층. 네트워크 인터페이스 계층 ──► 하드웨어 영역 (Wi-Fi, 이더넷)
```

'TCP/IP'는 프로토콜 두 개의 이름이 아니다. 인터넷 전체를 떠받치는 **프로토콜 군(Suite)**의 이름이다. OSI 5~7층을 따로 두면 연산 부담이 커지므로, 실제 구현에서는 최상위 소프트웨어가 세 층의 일을 한꺼번에 처리한다.

---

## 2. 계층별로 무엇을 실습하는가

| 계층 | 다루는 것 | 실습 |
|---|---|---|
| 1층. 네트워크 인터페이스 | 이더넷 프레임, MAC 주소, Wi-Fi | 패킷 캡처로 프레임 헤더 뜯어 보기 |
| 2층. 인터넷 | IP, ICMP, 라우팅, ARP | `ping`, `traceroute`로 경로 따라가기 |
| 3층. 전송 | TCP, UDP, 포트, 3-way handshake | 소켓으로 TCP·UDP 서버와 클라이언트 만들기 |
| 4층. 애플리케이션 | HTTP, WebSocket, MQTT, CoAP, DNS | 프로토콜마다 최소 클라이언트 짜 보기 |
| 최상단. API | 소켓 API, 라이브러리 API, REST API | 같은 통신을 저수준·고수준 API로 각각 구현해 비교하기 |

---

## 3. 애플리케이션 계층 프로토콜의 갈래

4층에는 성격이 다른 프로토콜이 여러 갈래로 나뉘어 있다. 무엇을 나르는지, 얼마나 가벼운지, 누가 먼저 말을 거는지가 갈래를 가른다.

* **요청-응답(Request-Response):** **HTTP** (웹의 기본), **DNS** (이름을 주소로 바꾸는 창구)
* **양방향 상시 연결:** **WebSocket** (연결을 끊지 않고 주고받는 통화)
* **발행-구독(Pub-Sub) 메시징:** **MQTT** (IoT 전용 경량 메시징), **Kafka** (대용량 로그 처리), **RabbitMQ** (작업 큐와 신뢰성 전달)
* **초경량 IoT:** **CoAP** (저사양 기기용), **XMPP** (메시징과 프레즌스)

여기서 짚어 둘 것이 하나 있다. **MQTT는 API가 아니라 애플리케이션 통신 프로토콜이다.** 둘을 섞어 쓰면 다음 절의 이야기가 어그러진다.

* **API:** 프로그램끼리 무엇을 어떻게 요청할지 정해 둔 규칙과 창구다. 메뉴판에 가깝다.
* **MQTT:** 데이터를 가볍고 빠르게 실어 나르는 방식이다. 배달 오토바이와 도로망에 가깝다.

---

## 4. API — 스택의 맨 위에 달린 문이자 제어판

API는 프로토콜 스택과 대립하는 개념이 아니다. **거대한 통신 엔진을 프로그래머가 쉽게 꺼내 쓰도록 껍데기에 달아 놓은 조작 버튼이 API다.**

### 4.1 역할로 본 관계

코드로 통신 프로그램을 만들 때 1층부터 4층까지의 로직을 매번 처음부터 짜지 않는다. 운영체제(OS)가 이미 프로토콜 스택을 안에 구현해 두었기 때문이다.

* **프로토콜 스택 = 엔진:** OS 깊숙한 곳에서 패킷을 쪼개고, 주소를 찾고, 유실을 확인하며 데이터를 실제로 날려 보내는 기계 장치다. 기능의 실체가 여기 있다.
* **API = 조작 핸들:** 그 엔진을 제어하도록 OS나 라이브러리가 내주는 `connect()`, `send()`, `publish()` 같은 함수다. 명령을 받는 창구다.

### 4.2 계층으로 본 관계

계층 구조로 보면 API는 프로토콜 스택 맨 위에 얹히는 소프트웨어 인터페이스 층이다.

```text
  [ 개발자가 만든 서비스 / 앱 ] (예: 스마트홈 제어 앱)
               │
               ▼
┌──────────────────────────────────────────────┐
│  ▶ API (Application Programming Interface)    │ ◀ 개발자가 누르는 "명령어 버튼"
└──────────────────────┬───────────────────────┘
                       │ (API 명령이 하부 스택을 깨운다)
                       ▼
┌──────────────────────────────────────────────┐
│  4층. 어플리케이션 계층 (MQTT, HTTP 등)       │ ──┐
├──────────────────────────────────────────────┤   │
│  3층. 전송 계층 (TCP, UDP)                   │   ├─► [ TCP/IP 프로토콜 스택 ]
├──────────────────────────────────────────────┤   │   (데이터를 실제로 나르는 엔진)
│  2층. 인터넷 계층 (IP)                       │   │
├──────────────────────────────────────────────┤   │
│  1층. 네트워크 인터페이스 계층 (Wi-Fi, 이더넷)│ ──┘
└──────────────────────────────────────────────┘
```

개발자가 API로 "MQTT로 '거실 전등 켜기' 메시지를 보내라"고 한 줄 요청하면, 그 명령이 아래 스택을 타고 내려간다. TCP 상자에 포장되고, IP 주소가 붙고, 무선 전파(Wi-Fi)로 날아간다.

### 4.3 자동차로 바꿔 보면

* **프로토콜 스택은 자동차의 구동 체계다.** 엔진, 변속기, 바퀴처럼 가속하고 방향을 바꾸고 제동하는 실제 기능의 집합이다.
* **API는 운전석의 페달과 스티어링 휠이다.** 운전자가 실린더의 움직임을 몰라도 페달만 밟으면 구동 체계가 작동해 차가 나아간다.

### 4.4 소켓 API — 가장 널리 쓰는 실례

전송 계층(TCP·UDP)을 조작할 때 전 세계 개발자가 공통으로 쓰는 표준 API가 **소켓 API(Socket API)**다. `socket()`, `bind()`, `listen()`, `accept()`, `connect()`, `send()`, `recv()` 일곱 함수로 스택과 대화한다. 실습에서는 이 함수만으로 서버와 클라이언트를 먼저 짜 보고, 그다음 같은 일을 고수준 라이브러리로 다시 짜서 무엇이 감춰지는지 확인한다.

## 5. 그래프로 본 IP와 TCP

* **📌 IP = 노드(Node):** 전 세계 수많은 기기 가운데 데이터가 닿아야 할 컴퓨터의 위치를 지정한다. (Host-to-Host)
* **🔗 TCP = 엣지(Edge):** IP가 찾아낸 노드와 노드 사이에 신뢰할 수 있는 가상 파이프라인을 연결하고, 흐름과 유실을 관리한다. (End-to-End)

> **요약:** IP 주소판을 보고 노드를 찾아가면 TCP가 그 노드 사이에 엣지를 잇는다. 그 위에서 HTTP나 MQTT 같은 애플리케이션 프로토콜이 데이터를 실어 나른다. 그리고 그 전부를 개발자가 API 한 줄로 부린다.

---

## 6. 실습을 밟아 가는 순서

1. **아래에서 위로 한 번.** 프레임과 IP 패킷을 눈으로 확인하고, TCP 연결이 열리고 닫히는 과정을 캡처해 본다.
2. **소켓 API로 직접.** TCP 에코 서버와 UDP 송수신기를 소켓 API만으로 짠다. 스택을 손으로 만지는 단계다.
3. **애플리케이션 프로토콜 갈래마다 하나씩.** HTTP, WebSocket, MQTT, CoAP로 같은 기능을 구현해 비교한다.
4. **같은 기능을 API 층위를 바꿔 가며.** 소켓 → 프로토콜 라이브러리 → REST 클라이언트 순으로 올라가며, 층을 올릴 때 무엇이 편해지고 무엇이 안 보이게 되는지 적는다.
5. **인캡슐레이션 추적.** API 호출 한 번이 각 계층에서 어떤 헤더를 덧입는지 캡처로 확인한다.
